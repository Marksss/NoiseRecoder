# 夜间声证（NoiseRecorder）

Kotlin 原生 Android 工程，最低 Android 11（API 30），compile/target SDK 35，当前版本 1.4.1。无需账号，声音和数据库保存在手机本地。`INTERNET` 权限用于仅绑定 `127.0.0.1` 的本机浏览器报告预览，没有上传或外部网络请求。

## 页面导航

顶部固定三个横向 Tab，各页独立滚动：

- **首页**：监听状态、实时声级、已保存的预约时段、每日预约勾选框、立即开启/停止值守，以及前往记录或设置的快捷入口。
- **记录**：按实际监听时段分组，所有录音默认收起（包括未归属时段的旧录音），点击展开后可回放、选择和删除单个文件，或删除整个时段；生成报告、浏览器查看，以及 Word / HTML / ZIP 报告导出菜单。手动展开后，切换 Tab 或 Activity 重建保留展开状态。
- **设置**：监听时间、阈值、校准、保存设置、电池优化、证据包与 CSV 导出，以及清理报告副本。

切换页面保留未保存的设置草稿、录音勾选和各页滚动位置；Activity 重建时恢复当前 Tab 和这些状态。在设置页修改后需点击“保存设置”，首页启动使用已保存参数；立即值守使用阈值和校准偏移，不受预约时段限制。

## 功能

- **立即值守**：立即采集声音、等待阈值触发录音，持续到手动停止，不受预约时段限制。
- **每日预约**：默认 **02:30–06:00**，可设置时间，支持跨午夜；时段开始自动采集，结束自动保存并释放麦克风，保留预约等待次日。结束时间不包含在监听窗口内。
- 默认 **45 dB** 触发阈值，可设置灵敏度和校准偏移。实时显示 dBFS 与估算声级。
- 内存循环缓冲保留触发前最多 **5 秒** PCM。刚进入监听时段时，预录音会从零逐步积累。
- 达到阈值后录制 **60 秒**；每个超阈值的 100 ms 音频帧都会把结束时间延至该帧之后 60 秒。所以首次触发后的文件通常约 65 秒（5 秒预录 + 60 秒正文）。
- 连续噪声期间自动延长，每 30 分钟无间断分文件，避免单文件过大；监听窗口结束或手动停止时立即收尾，即使不足 60 秒。
- 时间戳文件名，例如 `noise_20261023_023015_123_a1b2c3d4.wav`，按手机当地时间命名；CSV 使用 UTC ISO-8601 时间，保留毫秒。
- 录音索引保存开始触发时间、完整录音期间的最高 100 ms RMS 声级、时长、状态、触发阈值、校准偏移。触发事件另存时间、即时声级、文件名；连续超阈值时每秒最多保存一条事件，不影响逐帧延时。
- 保留 16 kHz / 单声道 / 16-bit little-endian PCM WAV 原始音频，无转码、降噪或事后剪辑。点击录音可调用系统播放器回放。
- 使用系统文件选择器导出 CSV 或 ZIP 证据包，ZIP 含原始 WAV、五张数据表的 CSV 和 SHA-256 清单。导出不会移动或删除原件。
- 支持逐段删除、勾选批量删除和全选；永久删除前确认。删除原始音频并留下删除标记，监听声级和超限统计继续保留。
- 记录页按监听时段分组，支持“删除整个时段”：同时删除该时段全部音频、录音索引、触发日志、声级及超限统计；没有触发录音的时段也可清理。与单独删除音频明确区分，均需确认。
- 选择实际监听时段生成内容一致的 Word / HTML 报告：监听范围、连续超限次数和时间明细、超限时长及占比、最大与能量平均声级、阈值和校准参数、声级曲线、录音及 SHA-256。
- HTML 可在手机浏览器打开，提供音频播放器与拖动进度；Word 内嵌原始 WAV 附件，可单独导出到电脑，支持的 Windows 桌面 Word 可双击附件调用播放器。手机 Word、网页版及部分安全策略可能禁止 OLE 播放。
- 可导出独立 HTML（内嵌音频）、独立 DOCX（内嵌音频）或完整 ZIP 报告包。报告是生成时的副本，后续删除原始录音不会修改旧报告；应用提供单独删除报告副本的入口。
- 麦克风前台服务 + 常驻通知 + PARTIAL_WAKE_LOCK，支持锁屏、充电整夜运行。通知提供停止按钮。
- 低存储停止并收尾；读取错误、系统静音麦克风时明确停止；进程意外退出后下次启动修复 WAV 文件头，并标记 `interrupted`。

## 构建与运行

1. 用 Android Studio 打开本目录。设置 Gradle JDK 为 **17 或更高的兼容 JDK**（推荐 Studio 自带 JBR）。工程使用 AGP 8.9.2、Kotlin 2.1.20、Gradle 8.11.1。
2. 在 SDK Manager 安装 Android SDK Platform 35、Build Tools 35.0.0。
3. 让 Studio 生成 `local.properties`，或手动指定 `sdk.dir`，例如 `sdk.dir=D:/Programer/AndroidSDK`。
4. 运行 `app`，允许麦克风和通知权限。Windows 命令行构建：

   ```powershell
   .\gradlew.bat testDebugUnitTest assembleDebug
   ```

   macOS / Linux：`sh gradlew testDebugUnitTest assembleDebug`。

5. APK 输出位置：`app/build/outputs/apk/debug/app-debug.apk`。

仓库包含 Wrapper 启动脚本与 JAR；第一次构建需要联网下载 Gradle 和构建依赖。

## 夜间使用

保存阈值和预约时段，在首页选择启动方式，再锁屏：

| 操作 | 行为 |
| --- | --- |
| 立即开启值守 | 立刻监听，超过阈值触发录音；预约结束时间不会停止它，需手动停止 |
| 勾选“预约每日值守” | 等待每天的预约时段，到点开启监听，结束后自动保存录音并释放麦克风，勾选保持、次日继续；若当前已在时段内，立即开始本次预约监听 |
| 取消勾选“预约每日值守” | 保存预约监听正在录制的音频、释放麦克风，取消后续每日预约 |
| 停止立即值守 | 保存立即监听正在录制的音频并释放麦克风 |

两种方式共用阈值、预录和连续触发延时逻辑。立即值守时预约框不可用，预约启用时立即启动按钮不可用，切换前需结束当前方式。预约勾选状态跟随实际服务，通知中停止、异常结束后自动取消勾选；返回首页也会同步。建议连接电源，并在“电池优化设置”中允许本应用后台运行；部分厂商还需在应用管理中允许自启动/后台活动。设置在**下次启动值守或预约**时生效，修改后应停止再开启。

Android 对从后台新建麦克风前台服务有限制，Android 14+ 也不允许普通应用在开机广播中直接启动此类服务。本工程从用户可见的 Activity 启动前台服务，在每日预约的待命期保持服务和通知，以便锁屏后进入时段。因此：

- **需要用户先开启值守**，不提供重启后静默启动麦克风。
- 每日预约待命时不创建 AudioRecord、不采集声音、不累计声级；时段结束关闭文件和监听时段，并停止、释放 AudioRecord。通知仍保留预约状态。
- 为维持锁屏调度，预约服务及部分唤醒锁会保持运行，待命仍有耗电，建议充电使用。预约不是无常驻服务的系统闹钟。
- 服务保持运行时，之后每天自动进入监听窗口；重启、强行停止、权限撤回、系统终止或音频错误后需要用户重新开启。立即值守通常需手动结束，系统终止、低存储或录音错误等情况也会结束并收尾。
- 锁屏运行依赖系统保留服务。前台服务和唤醒锁不能保证抵抗所有厂商杀进程策略，需要在目标手机实测。
- 默认音频源为 `UNPROCESSED`；设备不支持时系统可能回退到默认采集路径，硬件、自动增益、手机壳与摆放位置仍会影响结果。

平台依据：[麦克风前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types#microphone)、[后台启动限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)。构建版本依据：[AGP 8.9 兼容要求](https://developer.android.com/build/releases/agp-8-9-0-release-notes)。

## 声级校准

未经校准的手机 PCM 只能给出相对于数字满量程的 dBFS，不能直接给出真实 dB SPL。工程使用：

`估算 dB SPL = 20 × log10(RMS / 32768) + 校准偏移`

默认偏移 90 dB 是占位值，不代表已校准。用稳定声源，将手机麦克风与参考声级计尽量靠近；开启值守，点击“用参考声级校准”，输入同一时刻参考读数，计算偏移后保存，再停止并重新开启。建议在接近目标阈值的多个声级核对误差，改变手机、位置或音频路径后重新校准。

这里的“峰值”指所有 100 ms RMS 声级中的最大值，**不是瞬时声压峰值**。未实现 A/C 频率计权或 IEC 时间计权，不能把结果视为专业 dBA 测量。SHA-256 用于验证导出的文件字节，不能单独证明采集时间或法律真实性。

## 报告与删除

先停止值守，点击“选择监听时段并生成报告”，勾选所需时段。每次最多选择 31 个实际监听时段，默认选最近一个；单份报告的原始音频合计最多 400 MB，较多时可分批生成，避免超过 Word 可处理的文件规模。新版本开始记录完整的声级时间序列；升级前的录音可单独选择加入报告，但不会凭触发日志推算不存在的历史声级曲线和完整超限次数。

“一次超限”指连续达到或超过该时段阈值的一段声音，任一约 100 ms 帧回落到阈值以下即结束该事件。与每秒一次的触发日志、WAV 文件段数分别计数。每秒存储最小、最大及能量平均声级，绘制时间曲线；未采集到的时间不作为安静时段计算。实际监听时段结束、用户停止、异常中断都会写入状态。进程意外终止最多可能缺少最后约一秒尚未提交的声级摘要，恢复后的时段标记为 `interrupted`。

“在手机浏览器打开 HTML 报告”会启动仅本机可访问的临时预览，通知中可关闭，正常运行时约 10 分钟自动关闭。服务使用随机访问令牌、固定文件白名单和只读响应；音频支持 HTTP Range，便于拖动和继续播放。生成和导出均无需外部网络。若需要长期保留或脱离应用打开，导出独立 HTML，或解压完整报告包后保持 `report.html` 与 `audio/` 的相对位置。

Word 文档的 WAV 以 OLE Package 附件嵌入，不依赖手机路径和旁边的 WAV 文件。它不是 Word 页面内的 HTML5 播放条，实际双击播放取决于桌面 Word、Windows 音频关联程序和 Office 安全策略。HTML 提供跨设备的播放器；报告包也保留可直接打开的原始 WAV。

Word 的嵌入对象机制参考[微软的说明](https://support.microsoft.com/en-us/word/insert-an-object-in-word-or-outlook)。

删除前需停止立即值守或取消预约，并等待生成/导出任务结束。记录页每个时段显示实际起止时间、可用音频数量和状态，展开后可操作单个录音；未归属监听时段的旧录音单独显示。

- **删除这段录音 / 删除选中**：永久删除所选音频，数据库保留 `deleted` 标记、峰值、文件名、声级样本和超限事件，避免把“删掉不需要的音频”误当成“当时没有发生超限”。
- **删除整个时段**：确认后删除该时段全部音频（含之前已删音频的索引）、触发日志、每秒声级、超限事件及监听时段本身，后续报告选项也不再列出它。其他时段不受影响。

两种删除均有持久化标记，进程意外退出后下次恢复会继续清理；整段删除的数据库清理在同一事务中提交。如文件删除失败，会明确提示，已删除音频保留删除标记，剩余数据可刷新后检查、重试。已经生成的报告、报告中的音频及已导出的文件属于独立副本，需要另行删除；“删除已生成的报告副本”只清理应用内报告，不清理原始录音和监听统计。

## 数据与导出

### 电脑通过 USB 一键获取报告

先在手机的“记录”页生成报告，USB 连接电脑，开启 USB 调试并在手机上授权。双击仓库根目录 **`Get-Reports.cmd`**，自动获取最新完成的报告并打开电脑上的报告文件夹。

- 输出默认保存在 `exports/reports/日期时间_随机编号/`，每次独立保存，不覆盖之前的下载；该目录已加入 `.gitignore`。
- 获取内容包括 `report.docx`、`report.html`、声级曲线、`audio/` 原始报告音频及校验清单。HTML 的音频和图表需要保留相对目录；Word 可单独复制。
- 传输后自动校验音频 SHA-256。失败的目录保留 `INCOMPLETE.txt` 标记，请重新执行。脚本只读取手机报告，不删除手机数据，也不触发重新生成。
- 需要 Windows PowerShell 5.1 或 PowerShell 7、Windows 自带的 `tar.exe`，以及 Android SDK Platform Tools 中的 `adb.exe`。脚本从 PATH、`ANDROID_HOME` / `ANDROID_SDK_ROOT`、工程 `local.properties` 或默认 SDK 目录查找 ADB，也可手动指定路径。
- 直接读取应用私有目录使用 `run-as`，适用于本工程 **debug 安装包**（包括当前测试设备安装的版本）。正式 release 包请使用应用内“导出报告”保存到下载目录后再复制。
- 默认自动选择唯一的 USB 设备，多台设备时传入设备号。下载时请等待报告生成完成，并避免清理手机上的报告副本。

命令行示例（在工程根目录执行）：

```powershell
# 最新报告，指定已连接的测试设备
.\scripts\pull-reports.ps1 -Serial FA7951A00460

# 所有已完成报告，自定义电脑保存目录
.\scripts\pull-reports.ps1 -Serial FA7951A00460 -AllReports -OutputDirectory 'D:\Noise Reports'

# 手动指定 ADB，并在完成后打开报告文件夹
.\scripts\pull-reports.ps1 -AdbPath 'D:\AndroidSDK\platform-tools\adb.exe' -OpenFolder
```

若 PowerShell 执行策略阻止直接运行，可使用根目录的 `Get-Reports.cmd`，或执行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\pull-reports.ps1`。一键入口也接受上述参数，例如 `Get-Reports.cmd -AllReports -Serial FA7951A00460`。

### 数据文件位置与导出内容

- 原始音频：应用私有目录 `files/recordings/`。
- SQLite：`evidence.db`，含 `recordings`、`triggers`、`sessions`、`levels`、`exceed_events` 表。数据库 v1 → v2 自动迁移，保留旧录音。
- 证据 ZIP：`audio/*.wav`、上述五张表的 CSV、`SHA256SUMS.txt`、说明文件。
- 报告 ZIP：`report.docx`、`report.html`、曲线 PNG、`audio/*.wav`、SHA-256 和说明。独立 HTML 使用 Base64 内嵌音频，体积会比原始 WAV 更大，导出过程流式处理。
- “仅导出声级记录 CSV”输出 `triggers`，对应录音的整体峰值在 ZIP 的 `recordings.csv` 中。
- 为保证导出文件一致，导出前必须停止值守；导出过程中不能开启值守。CSV 使用 UTF-8 BOM，便于 Excel 打开中文。
- 文件访问仅通过系统导出目录或给播放器的单文件只读 URI 授权。无公开写入 Provider。
- 应用不自动清理录音。WAV 每分钟约 1.92 MB，整段连续 3.5 小时约 403 MB。剩余空间低于 32 MB 时不再开始新文件，值守中每 5 秒检查，低于 16 MB 时停止。请定期导出并管理手机存储。
- 卸载或清除应用数据会删除应用内原件，提前导出。导出失败时目标位置可能留有不完整文件，应重新导出。
- `complete` 正常结束；`window_end` 时段结束；`user_stop` 手动停止；`segment` 连续录音分段；`error` 运行异常；`interrupted` 意外中断后修复；`missing` 数据库对应文件缺失。

## 验证情况

已在本机通过全部 Kotlin 主源码编译检查，并通过 **14 项 JUnit 测试**，覆盖两种值守方式、时段边界、原有音频逻辑、报告能量统计、数据缺口、以及含 DIFAT 的大音频 OLE 附件字节完整性。离线校验脚本见 `scripts/verify-local.ps1`。

已使用 Pixel 2（Android 11 / API 30）完成 **11 项集成检查**，覆盖原有录音、声级记录、事件分段、两种报告、独立 HTML 音频字节、预览服务与 Range 请求、删除与副本隔离。另在手机 Chrome 实际播放报告音频，在桌面 Word 识别嵌入附件并渲染全部页面检查排版。

当前机器仅有 Android API 34 的 SDK，完整 Gradle 构建所需的 Gradle 8.11.1 下载超时。因此尚未验证标准 `assembleDebug` / Android Lint。真机测试包使用本地 Kotlin 2.1.10、SDK 34 和 Build Tools 33 离线打包，为兼容旧 D8 使用 JVM 1.8 字节码；正式 Gradle 工程配置仍为 Kotlin 2.1.20、JVM 17、SDK 35。运行时调用兼容 API 30；Android 13+ 通知权限按版本分支请求，清单额外声明 Android 14+ 麦克风前台服务权限。

测试步骤、范围与限制见 [docs/TESTING.md](docs/TESTING.md)。设备自动测试源代码在 `app/src/androidTest`。请只在专用测试设备运行，它会占用真实麦克风约 90 秒、锁屏再唤醒设备，并保留测试录音和缓存导出包。

交付后应在目标 Android 11、14、15/16 设备验证：锁屏跨时段、跨午夜、5 秒预录、重复触发延长、时段结束收尾、参考声级校准、充电整夜运行、麦克风竞争、权限撤回、低存储、进程终止后修复以及 ZIP 原件哈希。尤其需要在实际使用的手机上完成一整夜测试。
